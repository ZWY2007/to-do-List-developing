TO-DO LIST PROJECT - SHARED INTERFACES
Member 5 proposed alignment (based on Member 2's 2026-10-23 string-ID update)

1. DATA STRUCTURE

Each task is a dictionary containing:

- id: unique positive numeric STRING, e.g. "01", "02", "03"
      Numeric equivalents such as "1" and "01" mean the SAME task ID.
      New IDs are generated as strings with at least two digits.
- title: non-empty string
- priority: "High", "Medium", or "Low"
- completed: Boolean (True or False)
- due_date: date string in YYYY-MM-DD format, or None
- tags: list of strings

The tasks variable is a list of task dictionaries.

2. MEMBER 1 - FILE I/O

save_tasks(tasks, file_path="tasks.json")
Returns: True if successful, False if unsuccessful.

load_tasks(file_path="tasks.json")
Returns: a list of task dictionaries if successful, None if unsuccessful.

import_tasks(tasks, file_path)
Intended behavior: imported tasks must be validated, then the user must
confirm replacement; on success return the imported list, on cancellation
or error keep/return the original list.
NOTE: Member 1's current import_tasks() still expects integer IDs.
Imported task IDs must follow the shared STRING ID rule.
validate_task_list(data) may be reused to check imported data.

3. MEMBER 2 - ESSENTIAL TASK FUNCTIONS

add_task(tasks, title, priority, due_date=None, tags=None)
Returns: the new task dictionary if successful, None if unsuccessful.

modify_task(tasks, task_id, new_info)
Returns: True if successful, False if unsuccessful.

delete_task(tasks, task_id)
Returns: True if successful, False if unsuccessful.

toggle_completed(tasks, task_id)
Returns: True if successful, False if unsuccessful.

set_priority(tasks, task_id, new_priority)
Returns: True if successful, False if unsuccessful.

The task_id argument must be a positive numeric STRING.

4. MEMBER 3 - CLI

main()
Runs the main menu loop.

view_all_tasks(tasks)
Displays all tasks.

The CLI handles user input, displays messages, and catches ValueError from
validation functions. It uses each validator's RETURN VALUE.
The CLI must not convert IDs to int before calling Member 2's functions.
The existing load_tasks() failure (None) handling is already implemented.

5. MEMBER 4 - OPTIONAL FUNCTIONS

filter_tasks(tasks, filter_type, condition)
Returns: a list of matching tasks.
Accepts filter menu aliases "1" completed, "2" priority, "3" due_date,
"4" tags; condition for completed must be Boolean.

sort_tasks(tasks, sort_type)
Returns: a sorted list without changing the original list.
Accepts sort menu aliases "1" priority, "2" due_date, "3" id.

get_statistics(tasks)
Returns: a dictionary containing total, completed, uncompleted, and
completion rate.

6. MEMBER 5 - INPUT VALIDATION

validate_title(value)
Returns: a non-empty title string.

validate_task_id(value)
Returns: a positive numeric STRING ID, e.g. "1" -> "01", "01" -> "01".
Only ID FORMAT is checked, not whether the task exists.

validate_priority(value)
Returns: one of "High", "Medium", "Low".

validate_due_date(value)
Returns: a valid date string or None for blank/None.

validate_tags(value)
Returns: a list of tag strings; blank/None -> [].

validate_menu_choice(value, allowed_choices=None)
Returns: the chosen number as a string.
Without allowed_choices: main menu choices "0" to "11".
Filter submenu: pass ["0", "1", "2", "3", "4"].
Sort submenu: pass ["0", "1", "2", "3"].

validate_completed_filter(value)
Returns: Boolean. Accepts yes/no, true/false, 1/0, y/n (case-insensitive).

validate_task_list(value)
Checks a list of imported task dictionaries, rejects invalid and duplicate
IDs, and returns a validated NEW list (does not mutate original data).

Validation functions raise ValueError for invalid input.
They do not call input() or print().


7. SHARED RULES

- Function names and parameters must remain consistent.
- Every current task must have a unique ID by its numeric value.
- Priority values use consistent capitalization.
- Data-processing and validation functions do not handle CLI input/output.
- Invalid input and file errors must be handled safely.
- Filtering and sorting must not change the original task list.
- The main branch must not be overwritten without the agreed integration step.
